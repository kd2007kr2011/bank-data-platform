# D11：ODS 数据质量检查与坏数据隔离

## 一、今日学习内容

在 Source 数据抽取并装载到 ODS 的过程中，增加数据质量检查环节。对于不符合质量规则的数据，不直接写入正常的 ODS 目标表，而是将其写入 `ods.rejected_records`，记录原始数据、拒收原因、规则编码和批次信息，实现异常数据的隔离与追溯。

## 二、核心实现

1. **建立拒收表**：创建 `ods.rejected_records`，保存异常数据及对应的质量问题。
2. **编写质量检查规则**：在 `quality/ods_rules.py` 中检查交易 ID、账户有效性、交易时间和重复交易 ID 冲突。
3. **接入增量装载流程**：在 `load_incremental.py` 中加入质量检查，将正常数据写入 ODS，将异常数据写入拒收表。
4. **实现拒收记录去重**：利用数据哈希和数据库唯一约束，避免重复执行时重复写入相同的拒收记录。
5. **完成集成测试**：构造四类异常数据，检查拒收原因、数据库写入结果和重复执行行为。

## 三、主要质量检查规则

- 交易 ID 为空。
- 交易引用的账户不存在。
- 交易时间格式错误或为空。
- 同一交易 ID 对应不同的业务内容，存在数据冲突。

## 四、今日学习成果

完成了拒收表设计、Python 质量规则编写及增量装载流程的基本接入。集成测试中，四类规则均被触发，首次执行新增 5 条拒收明细，第二次重复执行新增 0 条，验证了拒收写入和幂等去重机制。

## 五、核心理解

数据质量检查不是简单地删除错误数据，而是在数据进入后续处理层之前识别异常、隔离坏数据、记录问题原因，使数据处理过程具备可追溯性，并降低异常数据对后续分析的影响。

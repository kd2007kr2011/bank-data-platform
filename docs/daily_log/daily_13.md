# D13：贷款与还款 DWD 学习总结

## 一、今日学习内容

今天主要学习了贷款业务从 Source/ODS 层到 DWD 层的数据处理流程，以及如何根据放款和还款记录生成指定日期的贷款本金快照。

### 1. 贷款业务 DWD 建设

首先，需要将贷款合同、放款和还款等业务数据进行规范化处理，形成 DWD 层的贷款相关数据表。

其中：

- `dwd_loan`：记录贷款合同的基本信息。
- `dwd_repayment_event`：记录每笔贷款的还款事件。
- `dwd_loan_snapshot`：记录每笔贷款在指定统计日的本金状态。

### 2. 贷款每日快照计算

贷款快照主要用于计算某笔贷款在指定日期的未偿本金。

核心计算公式：

**未偿本金 = 累计成功放款金额 − 累计成功归还本金**

在计算过程中，需要注意：

- 只统计状态为 `SUCCESS` 的放款和还款记录。
- 只统计截至指定日期已经发生的业务事件。
- 放款和还款应当分别按照 `loan_id` 进行聚合，再进行 JOIN，避免多对多关联造成金额重复计算。
- 归还利息不影响未偿本金的计算。

### 3. Python ETL 实现

在代码实现上，通过 Python 使用 `psycopg` 连接 PostgreSQL 数据库，执行 SQL 完成数据转换和写入。

主要流程：

1. 连接数据库。
2. 读取贷款、放款和还款数据。
3. 根据业务规则进行字段规范化和金额聚合。
4. 计算指定日期的贷款未偿本金。
5. 将结果写入 DWD 表，使用 `ON CONFLICT` 支持重复执行。

当前由于贷款相关的 ODS 数据处理流程尚未完善，暂时直接使用 Source 层进行计算。后续需要调整为正式的 `Source → ODS → DWD` 流程。

### 4. 数据分层理解

- **Source：** 保存源业务系统数据。
- **ODS：** 保留原始业务记录，执行基础质量检查和异常数据隔离。
- **DWD：** 对业务数据进行规范化、业务规则校验和事实建模，生成贷款明细及每日快照。

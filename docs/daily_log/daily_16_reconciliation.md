# D16：ODS → DWD 数据对账

## 一、学习目标

通过 SQL 对 Source、ODS、DWD 三层交易数据进行汇总和对比，检查数据在抽取、清洗和转换过程中是否保持一致，掌握数据对账的基本方法。

## 二、核心知识点

1. **数据粒度：** 明确交易数据的统计粒度，保证不同数据层之间可以进行有效比较。
2. **业务日期：** 根据交易时间提取业务日期，统一日期统计口径。
3. **交易类型与状态：** 按照交易类型（DEPOSIT、WITHDRAWAL、TRANSFER）和交易状态（PENDING、SUCCESS、FAILED）进行分类统计。
4. **金额统计：** 使用 COUNT、SUM 等聚合函数统计交易笔数和交易金额。
5. **数据对账：** 通过不同数据层的汇总结果进行比较，计算笔数差异和金额差异。

## 三、当天开发任务

创建文件：

`sql/checks/reconciliation.sql`

使用 SQL 完成以下工作：

1. 分别读取 Source、ODS、DWD 三层的交易明细数据。
2. 对 ODS 数据按照 transaction_id 进行版本排序，保留最新版本。
3. 按照 business_date、transaction_type、transaction_status 进行分组汇总。
4. 分别统计每日交易笔数和交易金额。
5. 使用 UNION ALL 和 GROUP BY 整合三层汇总结果。
6. 计算 Source → ODS、ODS → DWD 的笔数差异和金额差异。
7. 使用 CASE WHEN 判断对账结果，输出 PASS、WARN、FAIL。

## 四、核心实现逻辑

整个对账过程可以分为三个步骤：

**第一步：数据读取与汇总**

分别读取三层交易数据，按照统一的业务粒度进行分组，计算交易笔数和交易金额。

**第二步：数据比对**

将三层汇总结果进行整合，计算不同数据层之间的差异：

- Source 与 ODS：检查数据抽取是否完整。
- ODS 与 DWD：检查数据清洗和转换是否符合预期。

**第三步：一致性检查**

根据交易笔数和金额的差异判断数据是否一致。如果存在差异，则需要进一步定位具体交易，分析是否存在数据遗漏、重复或者业务规则过滤。

## 六、学习收获

D16 主要学习了数据仓库中的数据对账机制。

通过编写 SQL，读取 Source、ODS、DWD 三层交易数据，按照统一的业务统计口径进行汇总计算，再对比不同数据层之间的交易笔数和交易金额，判断数据是否保持一致。

今天最重要的认识是：

**数据经过 ETL 处理后，不能只关注数据是否成功写入，还需要通过对账机制验证数据的完整性和业务口径的一致性。**

如果发现数据差异，还需要进一步定位具体记录，分析差异产生的原因，确保下游分析人员使用的数据准确、可靠、可追溯。

## 三、核心知识点

### 1. 星型模型的实际应用

今天使用了 D15 建立的星型模型。

通过贷款事实表关联客户维度、地区维度和日期维度，将贷款业务数据转换为可以按照不同维度进行统计的数据。

其中：

- 事实表：保存贷款业务数据和相关金额指标。
- 客户维度：识别贷款所属客户。
- 地区维度：识别客户所属地区。
- 日期维度：识别贷款数据对应的统计日期。

通过代理键关联维度表，可以方便地按照不同业务维度进行汇总分析。

### 2. DWS 层指标汇总

今天主要使用以下 SQL：

- `GROUP BY`：按照客户、地区和日期进行分组。
- `COUNT()`：统计贷款笔数。
- `SUM()`：计算贷款余额和逾期余额。
- `FILTER`：筛选逾期贷款。
- `NULLIF()`：避免分母为零。
- `COALESCE()`：处理空值。
- `ON CONFLICT`：实现重复执行时的数据更新。

### 3. 贷款风险指标计算

贷款余额：

贷款当前未偿还的本金。

逾期余额：

本项目采用简化合成案例口径，将逾期贷款对应的全部未偿本金计入逾期余额。

逾期率：

逾期率 = 逾期余额 / 贷款总余额

当贷款总余额为 0 时，逾期率记为 0。

### 4. 幂等处理

客户和地区汇总表均使用：

`ON CONFLICT DO UPDATE`

当相同日期、相同客户或地区的数据再次装载时，更新原有记录，而不是重复插入。

保证汇总任务可以重复执行。

## 四、数据质量检查

今天主要需要检查以下内容：

1. 贷款事实表的数据是否成功装载。
2. 客户和地区维度关联是否完整。
3. 逾期余额不能超过贷款总余额。
4. 逾期贷款笔数不能超过贷款总笔数。
5. 逾期率必须处于 0 到 1 之间。
6. 相同日期下，客户汇总和地区汇总的贷款余额、逾期余额应该保持一致。

客户汇总和地区汇总的总金额一致，是验证不同维度汇总结果正确性的重要方式。

## 六、今日学习总结

今天主要完成了银行贷款业务在 DWS 层的日汇总。

首先，将贷款每日快照数据通过客户维度、地区维度和日期维度关联，装载到星型模型中的贷款日事实表。

然后，以贷款事实表为数据来源，分别按照客户和地区两个维度进行每日汇总，计算贷款笔数、贷款余额、逾期贷款笔数、逾期余额和逾期率。

通过今天的学习，进一步理解了 DWD 和 DWS 两层之间的关系：

- DWD 负责将业务数据整理成规范的事实数据。
- DWS 负责根据业务需求，利用事实表和维度表进行汇总，形成可以直接使用的业务指标。

**今天最重要的收获：**

数据仓库开发不仅仅是将数据存储到数据库中，更重要的是根据业务需求确定统计粒度，利用事实表和维度表组织数据，再通过 SQL 将底层业务数据转换为可以直接使用的统计指标。

例如，银行的业务分析人员不需要每次都从贷款明细中重新计算，而是可以直接使用 DWS 层提供的客户和地区贷款统计结果。
